# @edgekits/kernel

`@edgekits/kernel` is the core of the EdgeKits SaaS Kit for Cloudflare Workers: tenancy, policy and entitlements, billing events, provider ports, admin contracts, blueprint configuration, and the Astro and Hono middleware that wires them into an app. Its runtime dependencies are `zod` and `drizzle-orm`, with `hono` as a peer dependency, and it has no Cloudflare runtime dependencies beyond types.

The package is consumed through subpaths only: `@edgekits/kernel/tenancy`, `/policy`, `/events`, `/ports`, `/admin`, `/config`, `/astro` and `/hono`. The package root exports nothing. Inside the package, each subpath lives in `src/<name>/` with its public entry at `src/<name>/index.ts` and private code under `src/<name>/internal/`; a file may import its own subpath relatively, but reaches a sibling only as `@edgekits/kernel/<name>`. ESLint enforces this boundary.

`defineSaaS()` from `@edgekits/kernel/config` describes the SaaS in one typed blueprint, `edgekits.config.ts`: name and locales, tenancy, auth, roles, plans, billing, flags, AI, admin and the installed modules. Providers are chosen with tagged factories such as `tenancy.orgs()`, `auth.betterAuth()` and `billing.paddle()`. The input is parsed with a Zod schema that rejects a malformed blueprint, and the return value keeps the plan keys and the billing provider in its type. The kernel's default roles `owner`, `admin` and `member` are merged under the blueprint's own. `validateAgainstProviders(blueprint, capabilities)` is a separate step that checks the billing choices (currency, model, trials, proration) against a provider's capability manifest, such as `paddleCapabilities` from `@edgekits/kernel/ports`, and returns each unsupported choice with its path. `billing.products` maps provider product ids to a declared plan and a `subscription` or `lifetime` kind, and `billing.trial` (`days`, default 14, and `requiresCard`) describes the trial: without a card the kernel runs it with any provider, with a card the provider must support trials.

The same subpath types the Worker's environment. Each module declares its keys in a fragment, `defineEnv(name, { KEY: validator })`, with the validators `string()`, `number()`, `boolean()`, `url()`, `email()`, `oneOf([...])` and `json(schema)` (any synchronous Standard Schema, such as a Zod schema; the value may be a JSON string or a JSON value from Wrangler's `vars`), each with `.optional()` or `.default(value)`. Defaults are for non-sensitive fallbacks only: a credential never belongs in source. A key starting with `PUBLIC_` is a client value (Astro's convention), any other key a server value. `composeEnv(fragments)` merges fragments into one schema, merges a key two fragments declare the same way and refuses one they declare differently, naming both fragments (two `json()` validators are the same only when they share the schema object), and lists the server and client keys. `parseEnv(composed, env)` returns the typed, frozen values, treating an empty string as unset, or throws `EnvError` naming every missing or invalid key; `checkEnv(composed, values, { mode: 'local' })` reports the same problems as data, and `checkEnv(composed, names, { mode: 'names' })` takes only the names that are set (for example from `wrangler secret list`) and reports the required server keys that are missing. No message ever contains a value.

Tenant data lives in tables declared with `tenantTable()` from `@edgekits/kernel/tenancy`. It wraps Drizzle's `sqliteTable`, adds the `org_id` column and its index, and registers the table as tenant-scoped; the caller never declares `org_id`. A registered table is queried only through `ctx.db.repo(table)` on a `TenantContext`, whose `findMany`, `findById`, `insert`, `update` and `delete` add `org_id = ctx.orgId` to every predicate and set it on every insert; no method takes an org id. A `TenantContext` comes from `resolveTenant()`, which re-verifies membership on every call. Tenant tables are exported from `*.tables.ts` files, and the `kernel/tenant-table-access` lint rule allows importing them only from repositories (`src/**/repo.ts`), the tenancy subpath, a subpath's public `index.ts`, other `*.tables.ts` files, `drizzle.config.ts` files and tests. `/policy` re-exports its tables, `subscriptions` and `entitlementOverrides`, so an app's schema package can include them in its migrations. In development and tests, `tenantGuardLogger({ mode: 'strict' })` makes Drizzle throw on any select, update or delete of a tenant table without an `org_id` predicate. Per ADR-008 a table that declares `id` is keyed by `(org_id, id)`, so the same id can exist in two orgs and a column marked `.primaryKey()` is refused, while references between tenant tables go through `tenantReference()`, a composite foreign key that carries `org_id`, and a uniqueness violation raises `ConflictError`.

`@edgekits/kernel/policy` decides permissions and entitlements. `createPolicyEngine({ blueprint, counters })` takes the blueprint's `roles` and `plans` and returns an engine: `can(ctx, permission)` matches the actor's role against its permission globs (`*`, `<resource>.*` or an exact `<resource>.<action>`, with the kernel's default roles merged under the blueprint's), and `entitled(ctx, key, delta = 1)` resolves the org's entitlements and checks one key. A boolean value is a feature gate; a number is a limit, `-1` is unlimited, and otherwise the request is allowed when the live count from `counters[key]` plus `delta` stays within it; a key with no value is denied with limit 0. Denials are `Decision` objects; `requirePermission()` and `requireEntitlement()` throw them as `PolicyError`, which `errors()` turns into 403 or 402, and `entitlementFlags(ctx)` exposes the boolean values as flags. The pure `resolveEntitlements()` takes the org's rows from two tenant tables, `subscriptions` and `entitlement_overrides`, and resolves in this order: an unexpired admin override wins for its key (ADR-006); otherwise the plan comes from an active lifetime purchase, else the newest active subscription, else the newest trial whose `trialEndsAt` is still ahead, else the blueprint's `free` plan if it declares one, else no plan and no values. Expired trials and overrides are skipped, never changed. The tables are written only by the billing Workflow, by admin actions and by the kernel trial functions: `startKernelTrial()` starts the card-free trial that `billing.trial` with `requiresCard: false` describes (one per org, refused when the org already has a subscription row), `setTrialEnd()` moves its end, and `expireTrials()` marks due kernel trials as expired for a scheduled job, the one cross-org statement in the kernel, so it runs on a database handle without the strict tenant guard.

The request pipeline is plain Hono middleware from `@edgekits/kernel/hono`, used for API routes and pages alike. `tenant()` reads the session through a callback, takes an org named by an API key or trusted caller over the session's active org, calls `resolveTenant()` and sets `c.var.tenant`; no session, no org or a refused membership responds 404, and the org id is never read from a query string or client header. `errors()` is the `app.onError` handler: a `PolicyError` becomes 402 (entitlement) or 403 (forbidden) with the decision in the body, a `TenancyError` 404, a `ConflictError` 409, anything else 500 with no detail. `noStore()` adds `Cache-Control: no-store` to authenticated responses that set no cache policy of their own, and `sameOrigin()` rejects mutating requests from an origin outside the allowed list, or without an `Origin` but with a cookie. `securityHeaders()` sets a strict Content-Security-Policy, `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options` and `Permissions-Policy` unless the response already has them; Astro islands hydrate through inline scripts, so an Astro app passes its own `csp` with the `script-src` it needs rather than relying on the kernel default. `@edgekits/kernel/astro` copies `c.var.tenant` and `c.var.admin` into Astro locals with `toLocals()`.

`@edgekits/kernel/admin` provides `accessIdentity()`, which verifies the Cloudflare Access JWT in `Cf-Access-Jwt-Assertion` (RS256 against the team JWKS, with `iss`, `aud` and `exp` checked) and sets `c.var.admin`, or uses a configured identity in `mode: 'dev'`.

Every public function declares its return type (the lint rule `@typescript-eslint/explicit-module-boundary-types` enforces it), and `npm run typecheck` ends with `check:dist`, which builds `dist/`, type-checks its declarations from a consumer's side with `skipLibCheck` off, and imports every subpath with plain Node, no bundler. For that, every relative import in `src/` names the emitted file with a `.js` extension; the lint rule `kernel/relative-extension` enforces it.
